一个很新奇的llm上下文管理的思路（详见docs/）

但是经过实验证明，这个思路并不好用，targetedsurprise选中的文本直接就是文段的前512个token
这个思路其实和llm的context manage思路差不多，但是这个思路是直接把整个文段作为context，然后使用llm进行回答，但是这个思路有一个问题，就是llm的回答可能和文段本身有冲突，所以需要使用一个机制来判断llm的回答是否和文段本身有冲突，如果冲突，则需要重新生成文段，直到文段和llm的回答没有冲突为止。
综上，这个项目是不赞成使用的，因为这个思路会增加llm的计算量，并且会增加文段的生成时间，并且会增加文段的生成成本，并且会增加文段的生成难度，并且会增加文段的生成质量，并且会增加文段的生成速度，并且会增加文段的生成错误率。
